# DEEP BLUE GRID — RESPONSIVE UI CONTRACT

更新日: 2026-08-01

対象: Web版のスマートフォン、タブレット、PC表示、および将来のUnity / Android移植

## 1. この文書の位置づけ

本書は、DEEP BLUE GRIDの画面構造と操作感を端末ごとの偶然に任せず、Web版と将来のUnity版で同じゲームとして再現するための正本である。ゲームルールの正本は各ルール仕様書、表示用語の正本は `docs/TEXT_STYLE_AUDIT.md` とし、本書は「どの状態で、何を、どこに、どの大きさで、どう操作できるか」を規定する。

本文中の強度は次のとおり。

- **必須 / REQUIRED**: Web版の改修とUnity移植で維持しなければならない契約。未達ならリリース阻害として扱う。
- **推奨 / RECOMMENDED**: 現行実装からさらに品質を上げる項目。採用しない場合は理由を記録する。
- **現行 / CURRENT**: 2026-08-01時点のWeb実装の事実。必須契約より弱い箇所は「既知の差分」に列挙する。

解像度は端末名ではなく、CSS pxまたはUnityの論理dp相当で判定する。iPhone 17相当の縦表示 `402 × 874` を主基準にするが、その端末専用の座標や例外分岐を作らない。

## 2. 変更してはいけないUI原則

### 2.1 戦術図と指揮卓

- **必須**: 8×8戦術図は常に正方形で、縦横比を崩さない。
- **必須**: 戦術図、艦隊状態、選択中の兵装、実行・取消の関係が一つの視線移動で理解できる。
- **必須**: スマートフォンでは一度に一方の戦術図だけを表示し、同じ画面位置で `自軍戦術図` と `敵情図` を切り替える。縦に二枚を並べて手動スクロールさせない。
- **必須**: 横持ちタブレットとPCでは、表示領域が足りる限り両戦術図を同時表示し、その右に指揮卓を置く。
- **必須**: 配置、射撃、損害報告の各フェーズで、現在押すべき主要操作を画面下端または右側指揮卓に固定する。ブラウザのツールバーやOSのタスクバーより外へ押し出さない。
- **必須**: 盤上の照準、命中、ECHO、音紋、重要区画などは色だけで区別しない。形状、線種、短い符号を併用する。
- **推奨**: 戦術図から主要操作までのポインター移動は、PC横表示で画面幅の約1/3以内、スマートフォンでは親指の下半分の可動域内に収める。

### 2.2 一回の行動に必要な操作

- **必須**: 繰り返す基本行動は `兵装選択 → 戦術図で照準 → プレビュー確認 → 実行` とする。
- **必須**: この一連の操作に手動ページスクロールを要求しない。最初の画面到達時にページが動くことは許容するが、毎ターンの「微妙なスクロール」は不可。
- **必須**: 敵攻撃後は自動的に自軍戦術図を表示し、プレイヤーが損傷を確認して `戦闘記録へ記載` を押すまで次の自軍行動へ進めない。
- **必須**: `戦闘記録へ記載` 後は敵情図と通常砲撃、または任務で許可された先頭兵装を選択した指令待機へ戻す。
- **必須**: 攻撃演出中は入力をロックし、二重発射、二重リトライ、フェーズをまたいだ古い入力を受理しない。

## 3. 画面状態と遷移

Webの正本は `DeepBlueGrid.tsx` の `Phase` で、次の六状態を持つ。

| 状態 | 表示名 | 主表示 | 主要操作 | 次状態 |
| --- | --- | --- | --- | --- |
| `placement` | `FLEET DEPLOYMENT / 艦隊配置` | 自軍戦術図 | 艦選択、ドラッグ、回転、配置決定、交戦開始 | `player` または敵先攻の `enemy` |
| `placement` + MISSION | `SITUATION REVIEW` / `INTELLIGENCE REVIEW` | 両軍戦術図を切替確認 | 任務資料、固定配置、日誌、交戦開始 | `player` または `enemy` |
| `player` | `FIRE CONTROL` または `SONAR CONTROL` | 敵情図 | 兵装、照準、取消、実行 | `enemy` または結果 |
| `enemy` | `HOSTILE ACTION / 敵攻撃` | 自軍戦術図 | 原則として観測のみ | `review` または結果 |
| `review` | `DAMAGE REPORT / 損害報告` | 自軍戦術図 | LOG確認、戦闘記録へ記載 | `player` |
| `victory` / `defeat` | `AFTER ACTION REPORT` | 結果ダイアログ | LOG、戦術図レビュー、次へ、再試行、撤退 | 次の作戦、再試行、一覧、モード選択 |

### 3.1 フェーズ変更時の戦術図

- **必須**: コンパクト表示では `player` に入ると敵情図、それ以外の戦闘フェーズでは自軍戦術図を自動選択する。現行Webは `matchMedia` と `visibleBoard` で実装している。
- **必須**: 手動切替後は盤面アンカーを同じ表示位置へ戻す。現行Webは `scrollIntoView({ block: "start", behavior: "auto" })` を使用する。
- **必須**: 通常配置中の敵情図ボタンは無効。MISSIONの状況確認では両軍戦術図を有効にする。
- **必須**: 敵攻撃中、損害報告中、結果レビュー中も手動切替は残し、プレイヤーの確認を妨げない。
- **推奨**: Unityでは盤面オブジェクトを縦に移動させるのではなく、同じ表示枠へデータソースを差し替える。これにより向き変更時の座標ずれを避ける。

### 3.2 一時表示と判断時間

- **必須**: ターン帯、聴音結果、重要区画識別、特殊潜航などの演出は、元の状態変化を隠さない。
- **必須**: 演出終了だけを次フェーズ開始条件にしない。フェーズ状態を正本とし、UIアニメーションはその状態を表現するだけにする。
- **必須**: 複数区画攻撃は各着弾を識別できる間隔で順次表示し、最後の結果から敵ターン開始までに視認可能な間を設ける。
- **推奨**: 通常速度では、ターン帯約1.0秒、照準提示約0.7秒、各着弾約0.25秒、最終結果保持約0.8秒を初期値とする。端末性能でフレーム落ちしても結果を飛ばさない。

## 4. ビューポート分類

現行Webの主要判定は次のとおり。

- コンパクト操作: `(max-width: 1099px) and (orientation: portrait)` または `(max-width: 959px) and (max-height: 600px)`
- 右側指揮卓: `(min-width: 960px) and (orientation: landscape)`、`(min-width: 1100px)`、または `480–959px × 高さ600px以下の横表示`
- スマートフォン固定下部卓: `760px以下の縦表示`

移植先ではピクセル値を機種名へ置き換えず、下表のレイアウト能力として判定する。

| クラス | 目安 | 戦術図 | 指揮卓 | スクロール方針 |
| --- | --- | --- | --- | --- |
| P1 / phone portrait | 幅 `320–760`、縦 | 一枚切替 | 下部固定 | 戦闘ループは無スクロール。長文だけ内部スクロール |
| P2 / portrait tablet | 幅 `761–1099`、縦 | 一枚切替 | 下部stickyまたは固定 | 戦術図と主要操作を同時に維持 |
| L1 / short landscape | 幅 `480`以上、高さ `600`以下、横 | 一枚切替 | 右側指揮卓 | 指揮卓内だけスクロール可 |
| L2 / tablet landscape | 幅 `960`以上、横 | 二枚並列 | 右側指揮卓 | ページではなくLOG/資料だけ内部スクロール |
| D / desktop | 幅 `1100`以上 | 二枚並列 | 右側指揮卓 | ブラウザ・タスクバー込みの実表示高へ収める |

- **必須**: `width / height` と安全領域を使い、端末名やUser-Agentでレイアウトを選ばない。
- **必須**: 境界値で戦術図と指揮卓が同時に消えない。幅760/761、959/960、1099/1100、高さ600/601を回帰試験する。
- **必須**: 画面回転後にゲーム状態、照準、残弾、ログ、選択中の兵装を保持し、レイアウトだけを再構築する。
- **推奨**: Unityでは閾値を一か所の `ResponsiveLayoutProfile` 相当へ集約し、Sceneごとの個別判定を禁止する。

## 5. 主基準: iPhone縦持ち

基準ビューポートは `402 × 874 CSS px`。Safariのアドレスバーが展開・収納した双方で成立させる。

### 5.1 上から下の優先順

1. 作戦・海域・任務の進行表示
2. 現在フェーズと次の操作を示す状態帯
3. 自軍戦術図 / 敵情図の切替とLOG・音声・リトライ
4. 選択中の一枚の戦術図
5. その戦術図に対応する艦隊状態
6. 画面下端の配置卓、射撃指揮卓、損害報告、または結果レビュー

作戦開始後のコンパクト表示では、装飾的なブランドmastheadを畳み、状態帯を実質的なタイトルバーとして使う。モード選択時にはブランドとモード名を十分に表示する。

### 5.2 戦術図切替帯

- **必須**: 上端へsticky配置し、最低44×44 CSS pxの `自軍戦術図` と `敵情図` を並べる。
- **必須**: 現在の戦術図は色、枠、`aria-pressed` のすべてで示す。
- **必須**: コンパクト表示ではLOG、ミュート、リトライを同じ帯の44×44領域へ統合する。別の浮遊パネルを盤面へ重ねない。
- **必須**: 状態説明は狭ければ省略可能だが、切替ボタンとユーティリティは省略しない。
- **推奨**: 片手操作を考慮し、頻用するLOGと切替を中央から右側へ、破壊的なリトライは最右端かつ危険色へ置く。

### 5.3 盤面

- **必須**: 幅は安全領域内の100%以下、高さは残りの動的ビューポートから算出し、最低240 CSS pxを目標とする。
- **必須**: 8区画の一辺は、主基準で約44 CSS px以上を確保する。320px級では盤面外周を圧縮し、座標文字や装飾を小さくしてもタップ区画を縮めすぎない。
- **必須**: 盤面のポインター処理はブラウザのパンやズームと競合させない。現行Webの `.canvas-wrap { touch-action: none; }` を維持する。
- **必須**: タップ座標は描画解像度ではなく、表示Rectから8×8へ正規化する。UnityもCanvasScaler後のRectTransform座標を正規化する。
- **推奨**: 指が照準点を覆う場合は、選択中区画を一時的な外枠・座標ラベル・プレビューで補助する。勝手に隣接区画へ補正しない。

### 5.4 下部指揮卓

- **必須**: 幅760以下の縦表示では、指揮卓を左右のsafe areaと下端safe areaの内側へ固定する。
- **必須**: 射撃時は通常4列×2段、MISSIONは許可兵装に応じた3列を基本とし、取消と実行を最終段の右側へ置く。
- **必須**: 実行ボタンは画面右下の安全領域内に置くが、盤面・艦カードを覆うほど上へ張り出させない。コンテンツ側には指揮卓実高分の下余白を確保する。
- **必須**: 兵装が使用不能でも位置を詰め替えず、同じ兵装は同じ位置に保つ。ただしMISSIONで最初から存在しない兵装は表示対象から除く。
- **必須**: 使用不能状態は理由をタップまたはフォーカスで確認できる。`opacity` だけで説明を失わせない。
- **必須**: 配置卓は最大 `min(220px, 42dvh)` を目安に内部スクロールし、交戦開始ボタンを卓内下端にsticky表示する。
- **必須**: 損害報告の `戦闘記録へ記載` は右側に寄せ、最低58 CSS px高を確保する。
- **推奨**: 選択兵装の詳細は2.6秒の一時表示だけに依存せず、選択中は短い要約を継続表示できるようにする。

### 5.5 配置操作

- **必須**: 開始時に使用可能な全艦を自動配置済みとし、盤面の艦または艦カードをタップして再配置へ入る。
- **必須**: 艦をドラッグして移動でき、軽いタップで選択、選択後の有効位置タップで決定できる。ドラッグと決定タップを同一イベントとして誤判定しない。
- **必須**: `90°回転`、`配置決定` は二列にせず横二つで示す。回転は東・南・西・北を順に巡回し、360°で元に戻る。
- **必須**: 二本指タッチ、右クリック、`R` は回転の代替入力として残すが、これらを知らなくても画面上ボタンだけで完了できる。
- **必須**: `CLEAR`、`RANDOM`、`交戦開始` は下部配置卓内に置き、盤面へ重ねない。
- **必須**: MISSIONの固定配置では移動・回転・CLEAR・RANDOMを出さず、状況、制約、日誌、交戦開始だけを出す。
- **推奨**: 艦艇諸元は折り畳み、未展開時は艦名、コード、船体区画、役割の一行だけにする。攻略に必要な制約を折り畳み内へ隠さない。

## 6. 横持ちタブレットとPC

### 6.1 三領域レイアウト

- **必須**: 十分な横幅では `自軍戦術図 | 敵情図 | 指揮卓` の順に置く。
- **必須**: 二つの戦術図は同じ寸法、同じ垂直位置、同じ座標スケールで表示する。
- **必須**: 指揮卓幅は現行の `clamp(286px, 24vw, 326px)` を基準とし、盤面を不必要に小さくしない。
- **必須**: 配置中も同じ右側指揮卓へ艦艇諸元、回転、配置決定、CLEAR、RANDOM、交戦開始を置く。盤面の下へ追い出さない。
- **必須**: 射撃中は右側指揮卓へ選択兵装詳細、兵装ボタン、取消、実行、LOGを置く。
- **必須**: 指揮卓全体が表示高を越える場合、配置資料またはLOGだけを内部スクロールする。ページ全体は上下へ振らない。

### 6.2 表示高への対応

現行Webは動的ビューポート高に応じ、戦術図を次のように縮小する。

| 実表示高 | 現行方針 |
| --- | --- |
| `761–900` | ワークスペース高 `100dvh - 180px`、盤面は残り高へ追従 |
| `681–760` | 同じワークスペース高、盤面最大約370px |
| `680`以下 | 見出し・システム情報・クイックガイドを畳み、ワークスペース高 `100dvh - 140px`、盤面最大約330px |
| `600`以下かつ幅480–959 | 一枚の戦術図と幅218–310pxの右指揮卓。568×320では盤面150px、操作44pxを下限とする |

- **必須**: 1920×1080物理解像度でも、ブラウザツールバー、OSタスクバー、125%表示倍率を差し引いた実CSSビューポートで判定する。
- **必須**: 1366×768および1536×864の実表示高で、両盤面と実行ボタンが同時に見える。
- **必須**: 縦方向を確保するために本文を6–8pxへ縮めず、補助説明を折り畳むか内部スクロールへ移す。
- **推奨**: PCでは盤面と指揮卓の高さを揃え、LOGを余剰高の吸収領域にする。

### 6.3 短い横画面

- **必須**: 横幅があっても高さ600以下なら、一枚盤面＋右指揮卓へ切り替える。
- **必須**: 568×320級でタイトルやガイドを畳み、盤面、戦術図切替、実行の三つを優先する。
- **必須**: 画面回転直後に固定下部卓と右側指揮卓が同時表示されない。
- **推奨**: 480px未満の極端な横画面だけをP1相当へフォールバックし、必要なら一回の自動位置合わせとページスクロールを許容する。

## 7. Safe Areaと動的ビューポート

- **必須**: Web配布用HTMLは `viewport-fit=cover` を指定する。現行Viteエントリの `index.html` とNext経路の `app/layout.tsx` の両方で同じ契約を明示する。ズームを禁止する `maximum-scale=1` は指定しない。
- **必須**: 左右上端は `max(基準余白, env(safe-area-inset-*)))`、下端固定操作は `max(7px, env(safe-area-inset-bottom))` 相当を使用する。
- **必須**: `100vh` だけに依存せず `100dvh` を併記または使用し、iOS Safariのアドレスバー開閉に追従する。
- **必須**: ノッチ、Dynamic Island、ホームインジケータへ、操作ボタン、現在状態、閉じるボタンを重ねない。
- **必須**: Unityは `Screen.safeArea` をルートのSafeArea Panelへ反映し、回転、分割画面、ウィンドウサイズ変更ごとに再計算する。
- **推奨**: Safariの表示高が連続変化している間は毎フレーム大規模再配置せず、`visualViewport` の変更を短くまとめて反映する。
- **推奨**: Androidのジェスチャーナビ、3ボタンナビ、カットアウト、折り畳み端末のヒンジ領域を別々に確認する。

## 8. タッチ、マウス、キーボード

### 8.1 タッチ領域

- **必須**: Webの全操作対象は最低44×44 CSS px。隣接操作の間は最低4px空ける。
- **必須**: Unity / Androidは48×48dpを標準とし、狭い場合でも44×44dp未満にしない。見た目の枠より透明なRaycast領域を広げてもよい。
- **必須**: `閉じる`、戦術図切替、発射、配置決定、損害報告、戻るは例外なく最低値を守る。
- **必須**: 長押し、hover、右クリック、二本指ジェスチャーを唯一の操作経路にしない。
- **推奨**: 破壊的操作は一段階確認する。現行の敗北時WITHDRAWと同じく、初回で警告状態、二回目で実行とする。

### 8.2 入力対応表

| 意図 | タッチ | マウス | キーボード |
| --- | --- | --- | --- |
| 区画選択 | タップ | 左クリック | 矢印 / WASD後 Enter / Space |
| 艦移動 | ドラッグ | ドラッグ | カーソル移動と決定 |
| 回転 | 画面ボタン / 二本指 | 画面ボタン / 右クリック | `R` |
| 兵装選択 | タップ | クリック / hoverで説明 | `1–6` |
| 取消 | ボタン | ボタン | Escape |
| ミュート | ボタン | ボタン | `M` |
| LOGを閉じる | 44px閉じるボタン | 閉じるボタン | Escape |

- **必須**: ポインター種別の違いでゲーム結果を変えない。
- **必須**: タッチ開始で兵装説明を表示しても、そのイベントだけで発射しない。
- **必須**: フォーカス可能な要素上ではグローバルショートカットを奪わない。
- **推奨**: UnityのAndroid戻るボタンは、LOG/ダイアログを閉じる → 照準取消 → 撤退確認の順で処理し、即時終了にしない。

## 9. タイポグラフィ契約

### 9.1 役割

- **必須**: 英語コード、座標、時刻、残数は等幅系。日本語説明は読みやすい日本語フォントを使う。
- **必須**: 英語大文字は機器コード、日本語は意味と次の操作という現在のCIC文体を維持する。
- **必須**: 数字、座標、時刻はtabular figures相当で桁位置を揃える。
- **必須**: フォントが変わっても、文字列幅を固定値で仮定しない。

### 9.2 読みやすさの下限

以下は今後の収束目標であり、情報を削らず単に文字だけ縮小することを禁止する。

| 用途 | Web下限 | Unity / Android下限 | 行間 |
| --- | ---: | ---: | ---: |
| 主要ボタン名、フェーズ名 | 11 CSS px | 14sp相当 | 1.25以上 |
| 日本語本文、兵装説明、ログ | 10 CSS px | 13sp相当 | 1.45以上 |
| 副ボタン、残数、艦状態 | 9 CSS px | 12sp相当 | 1.35以上 |
| 装飾的な英語ラベル | 8 CSS px | 11sp相当 | 1.25以上 |

- **必須**: 重要な日本語、操作名、制約を8px未満へ縮小しない。
- **必須**: 長い兵装名は省略だけでなく、二行化、短い正式略号、詳細パネルのいずれかで識別可能にする。
- **必須**: ボタン主文と副文の行間を分離し、上下の文字が接触しない。
- **必須**: 文字を大きくすると枠を越える場合、枠の高さかレイアウトを変える。文字サイズをさらに落とすことで解決しない。
- **現行**: Webは `--font-tactical` に `ui-monospace`、SFMono / Menlo / Consolas / Roboto Mono、日本語のNoto / Hiragino / Yu Gothic / Meiryoを順序付きで定義している。これはOSフォールバックであり、配布フォント資産ではない。
- **移植契約**: Unity開始時は、本文・ボタンをBIZ UDPGothic Regular/Bold、英字コード・時刻・座標をIBM Plex Mono Medium/SemiBold、欠字時だけNoto Sans JPへフォールバックする。いずれもSIL OFL 1.1の正規配布物を取得し、ライセンス、upstream revision、SHA-256を保存する。詳細は `docs/UNITY_UI_HANDOFF.md` 4章を正本とする。
- **推奨**: Webにも同じupstream revisionのWOFF2をself-hostする場合は、本文用と英字コード用をrole classで分ける。OSフォントやfallbackの偶然でUnityと一致したことにしない。
- **推奨**: Unityのフォントアトラスは日本語本文をdynamicまたは必要文字集合で生成し、◆、◇、×、↻などの記号を欠落させない。操作アイコンはフォント字形ではなくSprite Asset化すると端末差が減る。

## 10. テキスト伸長とローカライズ

- **必須**: 実行時文字列をゲームロジックの条件に使わず、安定したIDから表示する。
- **必須**: `min-width: 0`、折返し、`overflow-wrap`相当を使い、英語兵装名や連続英数字で横スクロールを発生させない。
- **必須**: 省略記号やline-clampは補助説明だけに使用できる。任務目標、制約、残数、使用不能理由、結果、確認操作を切らない。
- **必須**: ボタンの視覚文が短縮されても、アクセシビリティ名には完全な意味を残す。
- **必須**: 日本語、英語、数字、記号が混在する実文字列で検査する。Lorem ipsumだけで判定しない。
- **推奨**: 擬似翻訳で本文を日本語の1.3倍、英語の1.5倍へ伸長し、全QAビューポートを通す。
- **推奨**: Unityの文字列はLocalization Tableへ外出しし、Webの `TEXT_STYLE_AUDIT.md` にある正本キーと対応表を持つ。

## 11. スクロール契約

### 11.1 ページスクロールを避ける領域

- **必須**: `player → enemy → review → player` の反復中、主要操作のための手動ページスクロールを発生させない。
- **必須**: スマートフォンの固定下部卓と本文の下余白を同じレイアウト変数から算出し、卓が艦カードや盤面下端を覆わない。
- **必須**: PCの戦闘ワークスペースは実表示高以内に収める。ブラウザページと右側指揮卓が同時にスクロールする構造を作らない。

### 11.2 内部スクロールを使う領域

| 領域 | 方針 |
| --- | --- |
| モード選択 | カード全体をダイアログ内でスクロール |
| MISSION INDEX | ヘッダ・分類タブを固定し、任務カード一覧だけスクロール |
| 配置卓 | スマートフォンのみ資料部を内部スクロール、交戦開始をsticky |
| CIC LOG | 下から開くdrawer内で全履歴をスクロール |
| 作戦日誌 | 日誌領域を独立スクロール。通常LOGとの二重スクロールを最小化 |
| 結果画面 | result card内部をスクロールし、背景ページを固定 |
| PC指揮卓 | LOGまたは資料領域だけスクロール |

- **必須**: 内部スクロールには `overscroll-behavior: contain` 相当を使い、端で背面ページへ意図せず伝播させない。
- **必須**: ダイアログ表示中は背景ページをスクロールさせない。
- **推奨**: スクロール領域は上端・下端のフェードまたはスクロールバーで、続きがあることを示す。

## 12. アクセシビリティ

- **必須**: すべての操作を実際のbutton相当で実装し、状態は `disabled`, `aria-disabled`, `aria-pressed` 相当で公開する。
- **必須**: キーボードフォーカスは高コントラストの輪郭で示す。hoverだけを選択表示にしない。
- **必須**: モード選択、MISSION INDEX、LOG、結果はdialogとして扱い、タイトルと閉じる操作を持つ。
- **必須**: ダイアログ表示時はフォーカスを内部へ移し、Tabを内部へ閉じ込め、閉じたら起点へ戻す。Unityでも選択フォーカスを復元する。
- **必須**: フェーズ、状態帯、聴音結果、識別警告はlive regionまたはUnityの同等な読み上げイベントへ通知する。ただし連続着弾を過剰に割り込ませない。
- **必須**: Canvasには `自軍戦術図8×8盤面` / `敵情図8×8盤面` の意味を付け、選択座標と結果を近接するテキスト表示にも反映する。
- **必須**: 危険、成功、選択、使用不能を色だけで示さない。
- **推奨**: 将来、64区画を読み上げ・キーボード操作できる非Canvasのアクセシビリティ層を用意する。
- **推奨**: 音声OFFでも全結果を視覚表示し、音だけの情報を作らない。触覚フィードバックを追加する場合も補助に限定する。

## 13. モーションと点滅

- **必須**: Webは `prefers-reduced-motion: reduce` でアニメーションを実質無効化する現行契約を維持する。
- **必須**: モーションを減らしても、ターン主体、CONTACT / NO CONTACT、HIT / SUNK、識別、結果が静止表示で判別できる。
- **必須**: 周期的なレーダー走査線、点滅、画面振動を情報取得の唯一の手段にしない。
- **必須**: 強い点滅を避け、短時間に3回を超える全画面明滅を作らない。
- **推奨**: Unity版に `演出軽減` 設定を設け、レーダー回転、shake、脈動、画面フラッシュを個別ではなく一括して静止表現へ切り替える。
- **推奨**: 通常モードでも、画面遷移を高速化する設定と判断待ち時間を短縮する設定を分ける。演出短縮が自動ターン進行の短縮にならないようにする。

## 14. 見た目の一貫性

- **必須**: 色の役割は現行CSS変数を正本とする。cyanは自軍・選択・正常、amberは確認・重要情報、dangerは敵・損害・破壊的操作、steelは補助情報。
- **必須**: 盤面、ボタン、テロップ、LOGは同じ細線・内枠・暗いCICパネルの語彙を使う。機能ごとに太さや角丸の異なる別アプリ風パネルを混ぜない。
- **必須**: 背景の走査線やノイズは操作領域のコントラストを下げない。文字と艦影より前面へ出さない。
- **必須**: UnityはWebのスクリーンショットを一枚絵として貼らず、背景、枠、グリッド、艦影、マーカー、文字を別レイヤーで再構成する。
- **推奨**: WebとUnityで共通の色トークン、線幅、余白、文字役割をJSONまたはScriptableObjectへ転記し、目視調整だけにしない。

## 15. Unity / Android移植時の構造

これは実装開始時に守るべき移植契約であり、ゲームロジックをUnity UIへ埋め込まない。

- **必須**: ゲーム状態、戦術図描画データ、表示文字列、レイアウト判定を分離する。同じ状態から縦・横UIを再構築できるようにする。
- **必須**: `Screen.safeArea` 内にRoot UIを置き、盤面はAspectRatioFitter相当で1:1を維持する。
- **必須**: CanvasScalerは論理解像度基準の `Scale With Screen Size` を使い、主基準を402×874相当に置く。幅だけ・高さだけへ固定せず、向きごとのLayout Profileでmatch値を調整する。
- **必須**: 右側指揮卓と下部指揮卓は同じPresenter / ViewModelを共有し、二重に残弾や選択状態を保持しない。
- **必須**: TextMeshProのAuto Sizeへ丸投げしない。役割別の下限と最大行数を明示する。
- **必須**: ScrollRectの入れ子を避け、MISSION一覧、LOG、結果のどれがスクロール所有者か明確にする。
- **必須**: 画面回転・アプリ復帰時に、フェーズ、表示中戦術図、照準、LOG位置、音声設定を失わない。
- **推奨**: 非自明なレイアウト分岐には `UI-CONTRACT:` コメントで本書の節を記す。例: `// UI-CONTRACT 5.4: bottom command dock must remain inside the safe area.` コメントは処理の言い換えではなく、なぜその制約が必要かを書く。
- **推奨**: Prefab名は状態ではなく役割で統一する。例: `PlotSwitcher`, `TacticalPlotView`, `BottomCommandDock`, `SideCommandRail`, `DamageReportPanel`, `OperationLogDrawer`。

## 16. 既知の現行Web確認事項

2026-08-01の改修で、短い横画面の4列化、128px盤面、固定卓の重なり、重要なMISSION制約のline-clamp、Next経路のSafe Area宣言、dialogのfocus trapは解消した。残る確認事項は次のとおり。

1. **フォント資産**: Webは改善済みの役割順フォールバックを使うが、端末内フォントである。Unityでは同じ指定を流用せず、配布可能な日本語SDFフォントを固定する。
2. **タッチ説明**: 縦画面の `weapon-peek` は一時表示である。選択状態、短縮名、残数、完全なアクセシビリティ名は常時残るが、長い説明の常設表示は今後の実機評価対象とする。
3. **極端な横画面**: 480px未満の横画面は右指揮卓の幅を確保できない。最低保証はスクロール可能な一枚盤面と下部卓とし、主対象にはしない。
4. **Canvasアクセシビリティ**: 盤面には意味のあるラベルがあるが、64区画を個別にキーボード巡回する非Canvas層は未実装である。
5. **大きな文字設定**: ブラウザの125%・150%拡大は継続検査する。Unityでは100% / 115% / 130%の文字設定を別途実装する。

実測結果は `docs/RESPONSIVE_UI_QA.md` を参照する。
