# DEEP BLUE GRID — Responsive UI QA Record

更新日: 2026-08-01
対象: Browser版。将来のUnity / Android比較基準

## 合格条件

- 横方向のページoverflowが0。
- 通常の配置・攻撃ループで、盤面と主操作が重ならない。
- iPhone縦持ち、タブレット縦持ち、PC横持ちは手動ページスクロールなし。
- 高さ600px以下の横持ちは一枚盤面＋右指揮卓とし、指揮卓を2列、操作高44px以上にする。
- MISSION一覧とLOGの長文だけは、専用領域内のスクロールを許可する。
- Browserのズームを禁止せず、Safe Areaを `viewport-fit=cover` と `env(safe-area-inset-*)` で守る。

## 視認確認

- 360×800と402×874では、作戦開始後の装飾mastheadを畳み、進行表示、状態帯、戦術図切替、盤面、下部卓を一画面に残した。
- 兵装ボタンは狭い画面だけ `GUN / F-4 / HARPOON / 8-INCH / MK-45 / SONAR` を表示する。詳細パネル、title、スクリーンリーダー名には正式名称を残す。
- 568×320と844×390では上部装飾、詳細文、常設LOGを畳む。LOG自体は切替帯の44pxボタンから開ける。
- 画面内の重要日本語を文字縮小だけで収めず、艦カード副文や長い説明の折畳みを優先した。

## 実戦フロー確認

- 402×874で通常砲撃の選択、照準、発射、敵行動、損害報告、`戦闘記録へ記載`、次の自軍行動までを通した。
- 損害報告中もページ寸法はviewport内に収まり、確認後は敵海域・通常砲撃選択へ戻り、不要な再スクロールは発生しなかった。
- LOGはページ全体ではなく一覧領域だけがスクロールする。表示直後のフォーカスは閉じるボタンへ移り、閉じた後は元の操作へ戻る。
- モード選択、MISSION一覧、LOG、結果画面はキーボードフォーカスをダイアログ内に保ち、`Escape` はMISSION一覧を閉じる。

## 自動検査

- `npm test`: 92件すべて成功（ゲーム規則、MISSION記録、HTML・レスポンシブ契約、production buildを含む）。
- `npm run build:pages`: GitHub Pages用静的ビルド成功。
- TypeScript単体検査では既存Cloudflare Worker型（`cloudflare:workers`、`Fetcher`、`D1Database`）だけが未解決。ゲーム画面と今回のレスポンシブ変更に起因する型エラーではない。

## Unity移植前に再実施する項目

1. iPhone Safari実機でアドレスバー展開・収納、ホームインジケータ、画面回転を確認。
2. Android Chromeでジェスチャーナビ、3ボタンナビ、表示サイズ100% / 115% / 130%を確認。
3. 全フェーズ（敵攻撃、損害報告、勝利、敗北、戦術図レビュー、LOG）を同じviewport表で再走査。
4. Unity移植対象commitを固定後、Web基準画像とUnity実機画像を同一論理解像度で比較。
